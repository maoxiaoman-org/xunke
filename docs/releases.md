# 版本发布维护说明

本仓库用于公开产品展示、安装包发布与问题反馈。构建程序仍在应用工程中维护；不要把整个应用工程或本机用户数据复制进来。

## 当前状态

macOS Apple 芯片版已在本地构建 1.2.3，尚未在本仓库公开发布。Windows 安装包尚未更新到这一版本，不应使用 macOS 的版本号描述它。README 中的两个下载入口均保持“准备发布”。

贸小满网站的 `/xunke/` 产品页已在网站工程完成，尚未部署。因此当前 README 的网站入口指向已存在的主页。产品页上线后，可将封面链接改为 `https://maoxiaoman.cn/xunke/`，并在 GitHub 仓库 About 的 Website 字段填写该地址。

## 发布一个版本

1. 在对应系统构建并验证安装包，记录平台、架构、版本号、文件大小和 SHA-256。
2. 在本仓库创建 GitHub Release，标签使用 `v版本号`。只有 Mac 就先发布 Mac，并在说明中明确 Windows 当前状态；不要放空链接或不存在的文件名。
3. 把 DMG / EXE 作为 Release 附件上传。安装包不进入 Git 提交。
4. 在版本说明里写清新功能、问题修复、支持的平台、安装方式和当前限制。测试版本使用 Pre-release 状态。
5. 更新中英文 README 的下载表，使用实际 Release 或附件链接。版本号、大小和架构以附件为准。
6. 在贸小满网站工程同步更新 `public/xunke/releases.json`，填写该平台真实的 `url`、`version`、`sizeBytes`、`publishedAt`、`sha256`，并同步页面版本进展。

当前不提供客户端自动下载安装更新。以后接入更新服务时，再增加对应的更新元数据及发布流程；仅上传一个 DMG 并不能启用自动升级。

## 可复用的版本说明格式

```markdown
## 本次更新

- 填写本次实际新增或改进的功能。

## 下载与安装

| 平台               | 架构     | 安装包           | 文件大小 | SHA-256    |
| ------------------ | -------- | ---------------- | -------- | ---------- |
| 填写实际发布的平台 | 填写架构 | 填写真实附件名称 | 填写大小 | 填写校验值 |

写明安装步骤及必要的首次启动说明。

## 已知限制

列出实际存在的限制，例如尚未提供的系统版本或自动更新能力。
```
